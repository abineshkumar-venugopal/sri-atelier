## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `app/page.tsx`. The page auto-updates as you edit the file.

This project uses [`next/font`](https://nextjs.org/docs/app/building-your-application/optimizing/fonts) to load Cormorant Garamond (display) and DM Sans (body).

## Styling conventions

Tailwind v4 + [shadcn/ui](https://ui.shadcn.com), utility-first. **Style in the
markup** — there is no stylesheet of component classes to keep in sync.
`app/globals.css` holds only the theme tokens and a small base layer.

**Where things live**

| Path | What belongs here |
| --- | --- |
| `components/ui/` | Design system. shadcn components (regenerated by the CLI) plus shared style constants. Generic, knows nothing about FORMA's data. |
| `components/` | App components. Knows about projects, services, team. |
| `lib/utils.ts` | `cn()` — merges class strings and resolves Tailwind conflicts, so `<Button className="px-14">` overrides the variant's `px-9`. |

**Design tokens** live in the `@theme` block and become real utilities:

- Colour — `bg-ink`, `text-paper`, `bg-mist`, `border-fog`, `text-ash`, `text-brass`, `bg-brass-dark`.
  `ash` is the secondary text grey; it is not called `slate` (collides with
  Tailwind's own scale) or `muted` (owned by shadcn).
- Type — `font-display` (Cormorant), `font-sans` (DM Sans), and the micro scale
  `text-micro` / `text-eyebrow` / `text-label`.
- Motion — `ease-forma` is the site's easing curve; `animate-fade-up`,
  `animate-fade-in`, `animate-scroll-pulse`.

Values off the default scale are written as arbitrary values
(`text-[1.3rem]`, `tracking-[0.18em]`) rather than rounded to fit.

**Rules of thumb**

- **Mobile first.** Unprefixed classes are the phone layout; `md:` and up is
  desktop. e.g. `grid-cols-2 md:grid-cols-3`, `px-6 md:px-15`.
- **Parent-driven state uses `group`.** A card marks itself `group`, its children
  react with `group-hover:`. Stateful chrome uses a data attribute plus
  `data-[…]:` / `group-data-[…]:` — see `components/Nav.tsx`.
- **Repetition becomes a component,** not a CSS class. Buttons and form fields
  are in `components/ui/`.
- **No `@apply`** outside the base layer.
- **The custom cursor is opt-in.** `components/CustomCursor.tsx` grows over
  `a`, `button`, and anything marked `data-cursor="hover"`. Add that attribute
  to new non-interactive cards.

**Adding a shadcn component**

```bash
npx shadcn@latest add <name>
```

Two things to fix afterwards: the CLI writes `import { cn } from "cn"` —
change it to `@/lib/utils`; and if the component depends on one that has been
restyled (usually `button`), the CLI will offer to overwrite it. Decline, or
overwrite and `git checkout --` the file back.

`--radius: 0rem` in `globals.css` keeps every shadcn component square, matching
the rest of the design. Overlays sit at `z-2000`, above the `z-1000` nav.
